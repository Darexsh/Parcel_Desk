# Nova Poshta (Ukraine)

Tracks Ukrainian Nova Poshta waybills through the current official public site's shipment API, including movements tied to a declared redirected waybill. It also takes Nova Post's international numbers, which novapost.com's tracker sends to the same API: SH or TN, two letters for the country and ten digits, at times after RS. Detection offers Nova Poshta for them at low confidence; SHOC, SHOP and SHOR are left to Ekart, whose numbers use them and whose letter pairs name no country. Nova Poshta Global numbers use a separate portal and are outside this adapter's input scope. Recognition asks Nova Poshta first for an export waybill, 595000 and eight digits, a prefix no other network's numbers have shown. Its other families share their 14-digit shape with DPD, BRT and others, so it is asked after them.

The `direct` step requests anonymous movement history without an API key or recipient phone. Completed and current movements establish progress; dated future milestones remain plans. Each movement must belong to the returned shipment, parcel or delivery reference. Return and payment references cannot establish forward delivery. Explicit timestamp offsets are preserved, and unknown status codes remain unmapped. Code 9 also closes a return at the sending branch, so its event name decides between delivered and returned. The parcel app's review reads the code alone (`statusMap`), so codes 9 and 102 stay open there. The schedule is the planned arrival at the recipient's branch or door, so it is dropped once the parcel waits there, is collected or goes back. The branch or locker of the arrival and collection events is the pickup point. Exports name their delivery partner abroad, UPS or GoFo Express, with its number; the order and Nova Post Global references are discarded. A single parcel's declared size is read; a multi-piece waybill has none.

After an inconclusive retrieval of a Ukrainian waybill, `summary` requests the older anonymous `TrackingDocument/getStatusDocuments` API. It reads every international number as unknown, so it is never asked about one. That fallback returns a status summary, with no invented scans; only an explicit receipt timestamp can date delivery. Personal shipment details and credentials from frontend bundles are discarded.

Live test: `NOVA_POSHTA_TRACKING_NUMBER=… npm run test:carriers:live -- carriers/nova-poshta`.
